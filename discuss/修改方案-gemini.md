# 蛇伤专病原型与版本规划改进讨论清单

作为产品经理，在盘点当前《人民蛇伤模块》规划与系统整体的信息架构（IA）、数据流（Data Flow）后，发现我们在**版本规划切分**和**前端页面原型（UX）设计**上存在若干明显断层和逻辑冲突。

为了保证项目后续研发和演示的逻辑闭环，我们需要对目前的规划进行以下重点改正：

## 1. 随访业务的“假闭环”与版本脱节
* **问题点**：患者端小程序在 **v1** 阶段就上线了「复查提醒」、「用药打卡」、「对话收集信息」；但在系统架构里，医生端的「随访计划管理」和内网的「随访模块」却排在了 **v2 / v3**。
* **体验风险**：典型的 C 端有功能、B 端没管理。如果 v1 没有医生后台支撑，患者在端上的打卡数据发给谁看？复查任务由谁触发？这会导致随访功能变成一个无法闭环的单机版“闹铃”。
* **改正方案**：
  * **选型 A（延后 C 端）**：砍掉 v1 患者端的打卡和提醒模块，将其挪到 v2，与医生端随访管理后台同步上线。v1 仅保留极简的患者就诊历史查看功能。
  * **选型 B（补全 B 端 MVP）**：在 v1 医生端原型中，补充一个极简版的「任务下发面板」，允许医生给当前患者简单挂载时间提醒节点，让整个业务流先在 v1 跑通。

## 2. AI Agent 辅助初诊的“无数据可用”危机
* **问题点**：医生端的「蛇伤判定标准（Agent 给出初诊建议）」放在了 **v2**，依赖底层高质量的治疗知识库。但决定数据质量的核心环节——「数据治理（脱敏、清洗、结构化映射等）」被规划在了 **v3**。
* **体验风险**：向客户演示 v2 原型时，如果没有规范的专病数据清洗做支撑，AI 的输出会被认为是不可靠的“黑盒”。
* **改正方案**：
  * 在 v2 的内网后台原型中，**必须前置**一个「专病特征库/知识库字典简易维护页」。
  * 前端原型交互上，要求 Agent 弹窗给出的每个建议，必须有可点击的**“推导依据/溯源链接”**，并在 UI 上展示匹配到的结构化历史数据片段，打消医生的疑虑。

## 3. MDT 与多中心转诊在 v1 场景中的“失真”
* **问题点**：业务规划将「MDT 多学科会诊」和「转诊」放在了 **v1**。但根据数据流规划，v1 只接入了“旧专病库”，缺乏医院当前 HIS/LIS 的直接数据支撑，且“患者 360 视图”也在 v2 才会做。
* **体验风险**：临床的 MDT 需要查看详尽的患者化验单、PACS 影像和历史医嘱。如果 v1 原型在 MDT 页面画出了这些内容，研发将无法兑现（因为没接入底层数据）。
* **改正方案**：
  * v1 前端原型在设计 MDT / 转诊页面时，**切忌画大饼**。UI 面板仅能展示基于“急诊 C 端上报的信息（照片/口述）”和“简单接诊信息”。
  * 建议在原型上明确打上 `[检验影像数据待 v2 HIS 接入后解锁]` 的占位提示框，以此来控制相关方的预期。

## 4. 防骚扰与消息管控机制的缺失（C 端体验红线）
* **问题点**：在随访与健康陪护场景下（v2），系统会通过小程序推送表单和知识提醒。但目前的医生 / 系统后台原型中，没有任何关于“推送限流”的配置页面。
* **体验风险**：容易出现触发器逻辑死循环或多医生并发操作，导致一天内向患者微信连发多条模板消息，引起反感和投诉。
* **改正方案**：
  * 在系统的全局管理或随访设置原型中，必须补充一个**「消息防轰炸/频次限制策略配置页」**（例如：设置单患者 24 小时内最多收到 2 条推送）。
  * 针对此类配置，前端需加上明显的规则拦截提醒和状态管理展示。

## 5. “冷热双通道”在日常工作流中的感知度不足
* **问题点**：我们在架构设计上有一大亮点——解决内外网隔离的“冷热分流摆渡通道”。但除了大屏，这个亮点在其他 B 端页面感知不强。
* **改正方案**：
  * 在内网「数据接入监控」原型页中，明确拆分出 **[热通道监控 (急救实时)]** 和 **[冷通道监控 (HIS离线入库)]** 两个不同的视图标签。
  * 在医生「救助接诊工作台」原型中，对来源于 C 端小程序的数据打上 **`[紧急外网实时同步]`** 等显著标签，凸显我们在复杂网络隔离环境下保证业务时效性的架构能力。

## 6. PC 端与 APP 端的“重复造轮子”风险
* **问题点**：转诊、MDT、患者消息这几个核心高频操作，在《系统信息架构》中同时出现在了“医生端 PC”与“医生端 APP”。
* **改正方案**：
  * 在前端原型的备注与研发交接文档中，明确指出这几个同名页面采用**响应式或单一组件封装**。
  * 它们的 UI 业务逻辑应当 100% 一致，仅在外层套壳（375px 手机壳 vs PC 全屏宽表）上有所区分，以避免“两套代码漂移”增加研发工作量。
