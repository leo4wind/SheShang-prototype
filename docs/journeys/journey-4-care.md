# 主线 4：患者陪护全流程（治后随访）

> 这条主线是患者出院后的**长尾**：复查提醒、用药打卡、随访问卷、知识推送、医患互动。它持续产出"日常数据"反哺主线 2，也让医生通过主线 3 看到患者长期变化。
>
> 写法套用 `journey-1-emergency.md` 的结构。

---

## 元信息

- **主导角色**：蛇伤患者（出院后）
- **参与角色**：接诊医生（互动 + 看报表）、系统（自动调度）
- **触发**：患者治疗结束/出院；之后按计划周期反复触发
- **节奏**：长周期（出院后 1 周、1 月、3 月、6 月、1 年）
- **跨终端**：患者小程序（主） + 医生 APP（互动）
- **关键成功指标**：随访填写率、用药依从率、复查到达率、患者满意度

---

## 端到端步骤

### 阶段 A · 随访任务生成（出院触发）

1. **[系统]** 患者出院 → 自动生成随访计划：
   - 出院后第 3 / 7 / 30 / 90 / 180 / 365 天各触发一次
   - 每次触发：复查提醒、随访问卷、知识推送 3 个动作
2. **[接诊医生]** 在 **医生 PC** 的「随访计划管理」可调整周期 / 增加节点 / 跳过节点
3. **[患者]** 在 **患者小程序** 出院当天看到「我的随访计划」时间轴

### 阶段 B · 复查提醒

4. **[系统]** 复查日前 3 天 → 微信模板消息推送 + 小程序内消息
5. **[患者]** 在 **患者小程序** 收到推送 → 点开进入「复查详情」
   → 看到：复查项目清单、推荐医院（沿用主线 1 的医院选择逻辑）、预约入口（v2 接挂号）
6. **[患者]** 标记「已完成」/「已预约」/「无法到达」
7. 「无法到达」时 → 进入备选：远程问诊（v2）/ 推迟（v3）

### 阶段 C · 用药打卡

8. **[患者]** 在 **患者小程序** 的「用药打卡」每日看到当天药品清单
   → 包含：药品名、剂量、时间、备注
9. **[患者]** 每次服药后点击「已服」/「已漏」/「调整剂量」
10. **[患者]** 看到「打卡日历」热力图，连续打卡有成就感激励（v2）
11. 漏服 → 30 分钟后推送一次提醒，仍未补打则记入"漏服记录"
12. **[接诊医生]** 在 **医生 APP** 的「我的患者-用药情况」看到所有患者的依从率
    → 依从率低的标红 → 可主动发起对话（接阶段 G）

### 阶段 D · 对话收集信息

13. **[系统]** 在固定节点（如出院后 7 天）启动「对话陪护」
14. **[患者]** 在 **患者小程序** 收到对话推送 → 进入「陪护对话」页
    → 像聊天界面，机器人/Agent 提问：
      - 「今天伤口怎么样？拍张照？」
      - 「有没有发热？体温多少？」
      - 「最近有没有头晕？」
15. **[患者]** 回答（文字 / 语音 / 图片）
16. **[系统]** NLP 解析回答 → 结构化为日常监测数据，进主线 2 治理通道
17. 关键指标异常（如体温 > 38.5） → 自动告警接诊医生

### 阶段 E · 随访问卷

18. **[系统]** 在随访节点推送「随访问卷」（量表 + 自由填）
19. **[患者]** 在 **患者小程序** 的「随访问卷」填写
    → 单选/多选/评分量表/自由填
    → 支持中途保存
20. **[患者]** 提交 → 看到"感谢，本次随访已完成"
21. **[系统]** 问卷数据 → 主线 2 治理 → 进专病库的"随访"维度
22. **[科研人员]** 在 **内网 PC** 「统计分析」按问卷批次查看群组趋势

### 阶段 F · 知识推送

23. **[系统]** 按患者标签（蛇种 / 阶段 / 并发症）推送个性化知识
24. **[患者]** 在 **患者小程序** 「知识中心」看到推送列表
    → 内容：文章 / 短视频 / 漫画
25. **[患者]** 阅读 → 系统记录阅读时长（v2）→ 反哺推送算法（v3）

### 阶段 G · 医患互动

26. **[患者]** 任何时候可在 **患者小程序** 「我的医生」发起咨询
    → 文字消息（v2）/ 语音消息（v2）/ 图片（v2）/ 视频（v3）
27. **[接诊医生]** 在 **医生 APP** 「患者消息」看到未读
    → 回复 / 转给上级 / 标记为问诊事件
28. **[医生]** 主动联系患者：标记关心、推送临时任务、调整随访计划

### 阶段 H · 长期数据汇总

29. **[患者]** 在 **患者小程序** 「我的健康」看到自己的长期趋势：
    - 用药依从率
    - 关键体征（体温、伤口情况）
    - 随访节点完成率
30. **[接诊医生]** 在 **医生 PC** 「我的患者」看群组视图

## 失败 / 边缘场景

| 场景 | 处置 | 原型是否展示 |
|---|---|---|
| 患者长期不打开小程序 | 短信兜底 + 紧急联系人提醒 | v2 |
| 复查无医院在身边 | 推荐线上复诊 / 转介当地 | v3 |
| 对话回答严重异常 | 立即告警医生 + 触发应急流程（回到主线 1） | v2 |
| 问卷填到一半弃填 | 24 小时后推送提醒续填 | v2 |
| 患者拒绝随访 | 标记为"已退出"，停止推送 | v1 必做 |
| 个性化知识推送被关闭 | 改为通用知识列表 | v2 |
| 医患互动咨询超过医生处置范围 | 提示挂号到院 | v2 |

## 评审检查清单

1. **节奏**：第 3 / 7 / 30 / 90 / 180 / 365 天的随访间隔是不是科室共识？
2. **问卷与对话**：「陪护对话」(D) 和「随访问卷」(E) 边界？会不会让患者感觉被问两遍？
3. **告警阈值**：什么样的对话回答 / 体征触发"立即告警医生"？需要科室定义
4. **闭环**：随访数据进了专病库（主线 2），又怎么回流影响下一次随访推送？
5. **激励**：用药打卡的成就感激励是不是必要？还是会让医疗场景"游戏化"得不合适？

## 系统约束（v2 评审反馈合并）

> 主线 4 的所有"系统主动推送"动作（复查提醒、对话发起、问卷推送、知识推送、医生侧异常告警）都受以下约束。**这些约束在原型阶段用一个独立的「推送引擎设置」管理页（v3）展示，v1/v2 直接 mock 到位**。

### 1. 频次控制（Rate Limiting）

- **单患者 / 单类型 / 单日上限**：例如同一类知识推送 24 小时内 ≤ 1 次；用药漏服提醒 ≤ 2 次/天
- **全局推送速率上限**：每秒推送数硬上限，超出排队，避免节点抖动
- **静默时段**：默认 22:00 - 07:00 不推送非紧急消息（紧急例外：异常告警）

### 2. 状态机判定

每个随访任务有明确状态机，**只能向下走，不能回环**：

```
未触发 → 已推送 → 已响应 → 已关闭
                ↘ 已超时 → 已关闭
```

- 已响应 / 已超时 / 已关闭的任务**不再二次触发**任何推送
- 状态切换写入审计日志

### 3. 死锁防护

下列闭环必须打断：
- 知识推送 → 患者阅读 → 阅读偏好更新 → 再推同类内容（限速 + 多样化采样）
- 异常告警 → 医生提醒 → 患者再回复 → 再触发告警（同一告警 30 分钟内合并）

### 4. 熔断与告警

- 推送速率突增（如 1 分钟内 > 历史均值 5 倍）→ 自动熔断 + 通知运维
- 单患者单日推送数超阈值（默认 5 条）→ 自动降级为只发紧急

### 5. 演示策略

原型阶段不实现真实推送，但 `P000 首页 / 演示模式开关` 启用后会在右上角展示一个"推送计数器"，让评审者直观看到 4 条主线在演示路径里**没有触发轰炸**。
