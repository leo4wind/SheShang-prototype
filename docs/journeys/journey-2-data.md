# 主线 2：数据治理全流程

> 这是 4 条主线里**最"看不见"但最重要**的一条 —— 它是其它 3 条主线的数据底座。原型阶段要让评审者**看到**数据是怎么从混乱变成可用的，否则专病库的价值讲不出来。
>
> 写法套用 `journey-1-emergency.md` 的结构。

---

## 元信息

- **主导角色**：数据管理员
- **参与角色**：科研人员（消费）、接诊医生（消费）、系统管理员（接口配置）
- **触发**：多源数据持续到达（HIS / LIS / PACS / 120 / 患者上报 / 旧专病库）
- **节奏**：批量任务（定时拉取） + 实时事件（c 端上报、就诊完成）
- **跨终端**：内网 PC（主） + 医生 PC（提供数据）
- **关键成功指标**：数据从落库到入专病库的"治理通过率"、人工质疑率、字段缺失率持续下降

## 端到端步骤

> **v2 评审已合并**：脱敏前置（D→C 调换为 C→D）；阶段 A 加冷热双通道说明；阶段 F 加质控查阅 D2 原文。

### 阶段 A · 数据接入（v1 旧库 / v2 多源对接，含冷热分流）

1. **[系统]** 通过 ETL 任务/接口拉取数据，按时效要求**冷热分流**（见 `data-flow.md` 总图）：
   - **热通道**（轻量清洗 + 脱敏 → 实时只读库）：120 出车、医生录入、患者小程序上报
   - **冷通道**（完整治理 → 专病库）：HIS、LIS、PACS、旧专病库
   - **C 端数据**走外网→内网的**隔离通道**，不直连内网
2. **[数据管理员]** 在 **内网 PC** 的「数据接入监控」看到各接口状态
   → 顶部 Tab 切换 **热通道 / 冷通道**
   → 列表：接口名、数据源、最近同步时间、本次抓取条数、错误率、所属通道
3. 出错时：点击进入「同步异常详情」→ 看到错误堆栈 + 重试按钮

### 阶段 B · 数据落库（按数据形态分桶）

4. **[系统]** 按数据形态自动分桶：
   - **结构化**：表单字段、数值（直接入结构化表）
   - **半结构化**：JSON、XML（入半结构化区，待结构化映射）
   - **非结构化**：病历自由文本、图片、PDF、录音（入 **D2 对象存储** + 元数据索引）
5. **[数据管理员]** 在 **内网 PC** 的「数据落库总览」看分桶情况
   → 看板：各形态条数、本周增量、占比饼图

### 阶段 C · 脱敏（**前置**，进入治理管线就脱敏）

6. **[系统]** 落库后立刻跑脱敏规则：
   - 姓名 → 张*、李*
   - 身份证 → 前 6 + 后 4
   - 手机 → 138****1234
   - 地址 → 截到区/县
   - 自由文本 → NLP 识别敏感信息后脱敏
7. **[数据管理员]** 在 **内网 PC** 的「脱敏规则管理」可调整规则、预览效果
8. **[原始数据]** 仍保留在 D2 对象存储，**仅供 G6 质控复核**和接诊医生 (C1) 急救场景查阅，访问走独立审计

### 阶段 D · 数据清洗（脱敏后跑清洗）

9. **[系统]** 在脱敏后的数据上跑清洗 pipeline：
   - **去重 / 格式化**：手机号、日期格式归一化（身份证已脱敏，按脱敏后的前 6 + 后 4 去重）
   - **基本校验 / 非法值过滤**：年龄 >150、血压为负等
   - **数据映射**：源系统字段 → 标准字段
   - **变量加工**：分级、类别转变量、记录合并、多选转单选、缺失值填补、变量拆分
10. **[数据管理员]** 在 **内网 PC** 的「清洗任务列表」看每个任务的输入条数、输出条数、丢弃条数、丢弃原因分布
11. 任务详情页可以下载清洗前/后样本对比 CSV（脱敏后）

### 阶段 E · 结构化映射

12. **[系统]** 跑映射 pipeline：
    - **标准编码映射**：ICD-10、SNOMED CT、LOINC（化验项）
    - **非结构化 NLP 处理**：从病历文本抽取结构化字段（蛇种、咬伤部位、咬伤时间、用药等）
13. **[数据管理员]** 在 **内网 PC** 的「映射工作台」看 NLP 抽取结果：
    - 左侧原始文本（已脱敏）、右侧抽取出的字段、置信度高亮
    - 低置信度的项目标红，等待人工确认
14. 人工确认/纠正抽取结果 → 反馈进入下一轮训练样本（v3）

### 阶段 F · 数据质量控制（可查 D2 原文复核）

15. **[系统]** 自动校验：
    - **逻辑性检查**：出院日期 < 入院日期、化验值在参考范围外
    - **配置校验**：用户自定义规则（血压为负、心率为 0 等）
16. **[数据管理员]** 在 **内网 PC** 的「质控工作台」看校验报告
    → 列表：记录 ID、患者姓名（脱敏后）、错误类型、字段、值
17. **[数据管理员]** 对可疑数据**发起质疑**
    → 创建质疑工单，关联记录、字段、问题描述
    → 工单详情页支持「查阅 D2 原文」按钮（走独立审计日志），可看到原始病历文本 / 报告单截图，避免脱敏后判不清是数据错误还是脱敏误伤
18. **[接诊医生]** 在 **医生 PC** 的「数据答疑」（或 APP 推送）收到质疑工单
    → 查看质疑 → 回复（确认原数据 / 修正）
19. **[数据管理员]** 审核答疑结果 → 通过则**锁定记录**（标记为已质控）
20. 锁定的记录进入专病库 D1 正式区，被 4 条主线消费

### 阶段 G · 入库 & 消费

21. **[科研人员]** 在 **内网 PC** 的「多维查询导出」按蛇种、地区、年龄分组查询
22. **[科研人员]** 在「统计分析」做按月趋势、用药构成分析
23. 任何角色都可以在「数据流转大屏」看到从源到专病库的实时流量（呼应 `data-flow.md`，**单页展示无钻取**）

## 失败 / 边缘场景

| 场景 | 处置 | 原型是否展示 |
|---|---|---|
| 源系统接口不通 | 监控告警 + 自动重试 + 邮件通知 | v1 必做（占位提示） |
| 数据条数突降 | 异常检测 + 告警 | v2 |
| 脱敏漏掉某些字段 | 人工抽样 + 反向补规则 | v2 |
| NLP 抽取大面积低置信 | 模型回退到旧版本 + 通知模型团队 | v3（提一下） |
| 质疑长时间无人响应 | 自动升级到上级 + 超时统计 | v2 |
| 锁定后发现错误 | 解锁需要审批，留审计日志 | v2 |

## 评审检查清单

2. **角色边界**：数据管理员 vs 接诊医生 在质疑/答疑的分工对吗？
