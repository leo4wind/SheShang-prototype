# 主线 1：蛇伤急救全流程

> 这是 4 条主线里**最有戏剧张力**、**跨终端最多**的一条，所以放在第一条写。它会自然牵引出主线 2（数据治理）该治理什么数据。
>
> 后面写主线 2/3/4 时，请套用这份文档的结构。

---

## 元信息

- **主导角色**：蛇伤患者、接诊医生
- **参与角色**：上级专家（如需转诊）、数据管理员（事后入库）
- **触发**：患者在野外被蛇咬伤
- **时长**：从被咬到入院治疗约 1-4 小时（黄金救助窗）
- **跨终端**：患者小程序 → 医生 PC → 医生 APP → 内网 PC（事后）
- **关键成功指标**：患者在 2 小时内到达**有对应血清**的医院、医生接诊前已掌握现场信息和初步判定

## 端到端步骤

> 步骤格式：`[角色] 在 [终端] 的 [页面] 做 [动作]，看到 [结果]`

### 阶段 A · 求救（0-5 分钟）

1. **[患者/家属]** 在 **患者小程序** 打开「求救首页」，点击「一键 SOS」大按钮
   → 系统自动定位、自动登记此次求救事件、推送给周边医生
2. **[患者]** 在 **患者小程序** 的「就近医院列表」看到按距离排序的医院
   → 每家医院显示：距离、是否有蛇伤救治资质、**血清库存（按蛇种）**、估计到达时间
3. **[患者]** 选择一家医院 → 进入「自救等待页」
   → 显示倒计时、医院路线、待办自救清单（占位先不放真实内容）

### 阶段 B · 现场信息上报（5-15 分钟）

4. **[患者/家属]** 在 **患者小程序** 的「现场信息上报」表单填报：
   - 拍照：蛇（如果还在）、伤口
   - 口述：被咬经过、当前症状（可语音）
   - 自动带入：时间、定位、紧急联系人
5. **[患者]** 看到「上报成功」反馈
   → 同时推送到接诊医生工作台

### 阶段 C · 远程救助（5-60 分钟，与 B 并行）

6. **[接诊医生]** 在 **医生 PC** 的「救助工作台」看到新警报
   → 工作台列表：待处理求救事件、患者位置、上报内容预览
7. **[接诊医生]** 点击事件 → 进入「患者实时视图」
   → 看到：患者上报的所有现场资料、定位、症状、估计 ETA、患者既往史（如果是回头患者，从专病库拉）
8. **[接诊医生]** 在「自救指引推送」面板选择对应的自救建议模板（绷扎/制动/避免吸吮等）
   → 一键推送到患者小程序
9. **[患者]** 在 **患者小程序** 的「就诊详情」收到自救建议
   → 按指引操作（占位 UI 即可）

### 阶段 D · 入院判定（到院后 0-30 分钟）

10. **[患者]** 到达医院 → 在 **患者小程序** 出示「就诊二维码」给前台
    → 系统标记事件状态：已到院
11. **[接诊医生]** 在 **医生 PC** 的「蛇伤判定」页面：
    - 上传伤口实拍图
    - 调用「图像识别」（v2，原型用 mock）→ 输出：可能蛇种 + 置信度
    - 调用「Agent 初诊建议」→ 输出：建议蛇种、推荐血清、治疗方案
12. **[接诊医生]** 参考 agent 建议 → 做实际判断 → 填写「就诊记录」表单
    → 包括：最终蛇种判定、血清用量、其它处置
13. **[接诊医生]** 提交就诊记录 → 进入「治疗中」状态

### 阶段 E · 治疗与记录（持续）

14. **[接诊医生]** 在治疗过程中可在 **医生 APP** 随时补录：化验、影像、用药、生命体征（多数从 HIS/LIS/PACS 自动拉，原型 mock）
15. 如需转诊 → 跳转到主线 3「医生工作站」（见 `journey-3-doctor.md`）
16. 治疗完成 → 患者出院

### 阶段 F · 入库与随访（事后 24 小时内）

17. **[数据管理员]** 在 **内网 PC** 的「数据治理」看到本次就诊记录进入治理流水线
    → 详细流程见 `journey-2-data.md`
18. 治理完成 → 患者档案进入「专病库」
19. 系统按规则触发主线 4「健康陪护」的随访任务（见 `journey-4-care.md`）

## 失败 / 边缘场景

| 场景 | 处置 | 原型是否展示 |
|---|---|---|
| 弱网 / 无网 | 电话/短信兜底（小程序展示 120 电话和短信模板） | v1 必做（占位即可） |
| 患者意识不清，家属操作 | 求救首页支持"代为求救"模式，多填一项关系 | v1 简化（同一表单） |
| 当地医院无对应血清 | 列表标红 + 提示「就近无血清，建议立即联系上级中心」+ 跳转转诊 | v2 |
| 定位失败 | 手动输入或者从地图选点 | v1 必做 |
| 蛇逃跑，拍不到 | 表单允许跳过照片，加文字描述选项 | v1 必做 |
| 急救途中症状恶化 | 患者端实时更新症状，医生工作台收到提醒 | v2 |
| 患者重复求救 | 系统识别 24 小时内同一患者，提示是否关联既有事件 | v3 |

## 依赖的数据 / 模块

| 数据 | 来源 | 在原型中如何处理 | 对应模块 |
|---|---|---|---|
| 医院列表 + 资质 | 系统管理员维护 | mock 5-10 家医院 | 应急求救/医院维护 |
| 血清库存 | 赛伦生物接口 | mock 数据，标 `[算法接入点]` | 应急求救 |
| 地图（POI、路径） | 高德 / 腾讯地图 SDK | 用静态截图或简单 canvas 占位，标 `[SDK 接入点]` | 应急求救 |
| 患者基础信息 | 患者注册 / 历史档案 | mock 一份患者数据 | 患者 360 |
| 既往史 | 专病库 | 调用 mock 接口，体现"从专病库拉" | 专病库 |
| 蛇种识别 | 图像识别算法 | mock 一个固定结果，标 `[算法接入点]` | 质控/判定 |
| 初诊建议 | Agent | mock 一段建议文本，标 `[算法接入点]` | 质控/判定 |
| 化验/影像/用药 | HIS / LIS / PACS | mock 数据 | 专病库（v2 数据接入） |

## 评审时的检查清单

写完后拉团队对一遍，重点问：

1. **角色**：步骤里出现的角色是否都在 `roles.md` 里？
2. **缺步**：从「被蛇咬」到「出院」之间有没有遗漏的关键交互？
3. **数据**：依赖数据表里有没有"哪个数据现在还没采集渠道"的硬伤？
4. **跨主线**：步骤 15（转诊）、17（入库）、19（随访）的跳转关系对不对？
5. **可演示**：评审者按步骤 1→19 走一遍，能不能讲通一个完整的故事？
