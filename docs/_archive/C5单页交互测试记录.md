## 重点说明

P110 和 P111 的交互控件可以渲染，但按钮/控件重复较多：

- P110 每个服药时间都有一组「已服 / 漏服」按钮。
- P111 同时存在快捷回复 chip、输入框发送、图片按钮等多个交互入口。
- 自动化定位重复文案时容易命中多个元素，因此本轮只做了页面渲染和代表性点击抽检。

建议最终人工验收时使用同一个浏览器会话，从左侧菜单进入页面，不要直接地址栏跳转。这样可以避免 Pinia 内存态在整页刷新后丢失，尤其适合验证用药状态、陪护对话进度等 demo 状态。

## 建议人工复测步骤

### P110 用药打卡

1. 从左侧菜单进入「患者端（小程序）/ 健康陪护 / 用药打卡」。
2. 记录顶部「今日依从率」初始值。
3. 点击第一条药品的「已服」，确认按钮变为「已服 ✓」标签。
4. 确认顶部圆环百分比提升。
5. 点击另一条服药时间的「漏服」，确认按钮变为「漏服」标签。
6. 确认页面出现漏服记录反馈，且整体布局无跳动、无遮挡。

### P111 陪护对话

1. 从左侧菜单进入「患者端（小程序）/ 健康陪护 / 陪护对话」。
2. 连续点击快捷回复，例如「伤口好转」「体温正常」「发伤口照片」。
3. 确认聊天列表追加患者消息和助手回复。
4. 继续发送数轮，直到出现「本次陪护对话已完成」。
5. 确认输入框和发送按钮禁用，继续点击不会重新开启对话。

## 当前风险

- 这些页面的状态主要存在 Pinia 内存中，浏览器整页刷新或直接地址栏跳转可能导致状态重置。
- 若后续评审要求稳定自动化回归，建议给相关 store 增加 `localStorage` 持久化，或增加 `data-testid` 以降低重复按钮定位成本。

## 验收建议

本轮可以认定 C5 页面视觉和基础控件渲染正常；P110、P111 建议安排一次人工同会话复测后再勾选为完全通过。
