# 主线 3：医生工作站全流程

> 这条主线串联**质控 + 多中心分诊 + 培训**三个模块，是医生侧的"日常工作流"。主线 1 的步骤 11-15 是它的入口之一（蛇伤判定后视情况转诊/MDT）。
>
> 写法套用 `journey-1-emergency.md` 的结构。

---

## 元信息

- **主导角色**：接诊医生（一线）、多中心医生（上级专家）
- **参与角色**：系统管理员（权限）、培训对象（基层医生）
- **触发**：蛇伤诊治中遇到疑难/重症，或日常培训需求
- **节奏**：实时（转诊 / MDT）+ 异步（培训 / 共享 / 权限）
- **跨终端**：医生 PC（值班/办公）+ 医生 APP（移动/查房）
- **关键成功指标**：转诊响应时长缩短、MDT 召集成功率高、基层医生独立处置能力提升

---

## 端到端步骤

### 阶段 A · 蛇伤判定（细化主线 1 阶段 D）

1. **[接诊医生]** 在 **医生 PC** 的「蛇伤判定」上传伤口图 + 现场拍到的蛇图
2. **[系统]** 调用图像识别（mock）→ 返回可能蛇种 + 置信度
3. **[系统]** 调用 Agent → 返回初诊建议、推荐血清、治疗方案、注意事项
4. **[接诊医生]** 看到「Agent 建议面板」：
   - 左侧：识别结果 + 建议
   - 右侧：可参考的相似历史病例（从专病库拉）
   - 底部：医生最终判定表单（可勾选采纳/修改建议）
5. **[接诊医生]** 提交最终方案 → **就诊记录** 自动保存判定过程（含 agent 输出 + 医生决策），供后续质控复盘

### 阶段 B · 转诊发起（重症 / 无血清场景）

6. **[接诊医生]** 判断需要转诊 → 点击「发起转诊」
7. **[接诊医生]** 在 **医生 PC** 的「转诊申请」表单填：
   - 接收医院（按主线 1 阶段 A 的血清匹配逻辑筛选）
   - 转诊原因、紧急程度
   - 患者现况快照（自动从就诊记录抽取）
   - 转运方式
8. **[接诊医生]** 提交 → 系统推送到接收医院的值班医生 APP
9. **[接收医院医生]** 在 **医生 APP** 收到推送 → 进入「转诊申请详情」
   → 看到患者完整资料、转出医院联系方式
10. **[接收医院医生]** 接受 / 拒绝 / 申请补充资料
11. **[接诊医生]** 看到接受确认 → 进入「转诊跟踪」面板（运送中、已到达）

### 阶段 C · MDT 多学科会诊

12. **[接诊医生]** 遇到疑难病例 → 点击「发起 MDT」
13. **[接诊医生]** 在 **医生 PC** 的「MDT 邀请」选择专家：
    - 按专科（毒蛇咬伤、急诊、肾内、血液…）筛选
    - 按医院/职称筛选
    - 选择多名专家、设定会诊时间
14. **[接诊医生]** 上传病例资料（病历、影像、化验）→ 发起邀请
15. **[受邀专家]** 在 **医生 APP** 收到邀请 → 接受/拒绝
16. **[受邀专家]** 在约定时间进入「MDT 会诊室」（v1 占位 UI，v2 接视频 SDK）
    - 共享病例资料
    - 讨论区（文字 + 语音）
    - 投票/共识机制
17. **[接诊医生]** 整理 MDT 结论 → 写入就诊记录

### 阶段 D · 共享患者

18. **[接诊医生]** 在「患者 360」搜到一名患者 → 点击「共享给医生」
19. **[接诊医生]** 选择共享对象 + 共享范围（基础信息 / 完整资料）+ 有效期
20. **[被共享医生]** 在 **医生 PC/APP** 的「共享给我的患者」看到一条记录
    → 在有效期内可查看，到期自动收回

### 阶段 E · 权限管理（系统管理员侧）

21. **[系统管理员]** 在 **内网 PC**（或医生 PC 管理后台）的「角色与权限」：
    - 维护角色（接诊医生、多中心医生、专家、培训对象、管理员）
    - 给角色分配菜单权限、数据权限（按医院/科室）
    - 维护用户 ↔ 角色绑定
22. **[系统管理员]** 审批用户加入医生组 / 专家组的申请

### 阶段 F · 培训中心

23. **[基层医生]** 在 **医生 PC/APP** 的「培训中心」浏览资料：
    - 上级医生上传的指导视频 / 文档 / 病例集
    - 按蛇种、按场景分类
24. **[基层医生]** 学习 → 完成测验（v2 占位）
25. **[上级医生]** 在「培训管理」上传资料、看学习数据

## 失败 / 边缘场景

| 场景 | 处置 | 原型是否展示 |
|---|---|---|
| 转诊接收方长时间无响应 | 自动升级到第二顺位医院 + 短信兜底 | v2 |
| MDT 专家全部拒绝 | 自动推荐替补专家池 | v2 |
| 共享患者后被共享人误操作 | 操作审计 + 撤回机制 | v2 |
| 跨医院权限冲突 | 数据脱敏后再共享 | v2（提一下） |
| Agent 建议明显错误，医生不采纳 | 医生标记"不采纳"+ 原因 → 反馈到算法侧 | v2 |
| 培训资料违规内容 | 上传时审核 + 举报机制 | v3 |

## 依赖的数据 / 模块

| 数据 / 能力 | 来源 | 在原型中如何处理 | 对应模块 |
|---|---|---|---|
| 患者历史档案 | 专病库（主线 2 产物） | mock 一份完整患者档案 | 患者 360 |
| 医院 + 资质 + 血清库存 | 主线 1 维护 | 复用主线 1 mock | 应急求救 |
| 医生通讯录 + 专科 | 系统管理 | mock 10-20 个医生 | 权限管理 |
| 视频会议 SDK | 第三方（v2） | 占位 UI，标 `[SDK 接入点]` | MDT |
| 图像识别 / Agent | AI 团队 | 复用主线 1 mock | 质控/判定 |
| 培训资料库 | 上级医生上传 | mock 5-10 份资料 | 培训 |

## 评审检查清单

1. **入口**：转诊 / MDT / 共享患者 三种动作的入口在哪里发起最自然？是不是都在「就诊记录」里集中？
2. **专家池**：MDT 的专家来自哪里、怎么维护？要不要新增"专家库"页面？
3. **跨院数据**：跨医院共享患者时数据脱敏强度？是不是一条独立的规则？
4. **培训和质控**：培训中心的内容和质控判定（agent 建议复盘）有没有联动可能？
5. **v 划分**：权限管理是不是 v1 必做？没有它其它流程跑不通
