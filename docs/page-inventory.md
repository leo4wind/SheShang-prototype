# 页面清单（Page Inventory）

> 这是 Week 1 的**最后一份文档**，把 4 条 journey 反推的页面 + IA 补充的页面汇总成一张可执行的清单。Week 2 起按这张表的路由一一占位，按 v1→v2→v3 顺序填实。
>
> 命名规则：临时 ID（J1-01 等）作废，统一改用 `P###` 三位数。新增首页 `P000`。

---

## 规模与节奏

| 范围 | 页面数 | 估时 | 周次 |
|---|---|---|---|
| v1（4 条主线骨架可演示） | 25 | ~ 15 工作日 | W2 末 - W5 |
| v2（4 条主线完整 + 多终端切换） | 19 | ~ 12 工作日 | W5 - W7 |
| v3（数据治理工作台 + 大屏） | ~ 10 | 后续迭代 | W8+ |
| **合计可见页面** | **~ 54** | | |

> 估时按"低保真 + Element Plus 骨架 + mock 数据"测算，包含路由、骨架、基本交互、mock。不含视觉打磨和真实接口。


## v1 必做清单（W2 末 - W5 完成）

按主线编织顺序做，**不要**按"先把医生端全做完再做患者端"的横向方式做。建议顺序：

**主线 1 急救（W2 末 - W3）**：P000 → P101 → P102 → P103 → P104 → P105 → P201 → P202 → P203 → P205 → P106 → P107

**权限/系统底座（W3）**：P402 → P403 → P119 → P118

**主线 3 医生协作（W4）**：P206 → P207 → P208 → P209 → P210 → P211 → P212 → P213 → P221

**主线 4 患者陪护（W4 末 - W5）**：P108 → P109 → P110 → P111

v1 完成后，**做一次内部走查**：从 `P000` 出发，4 条主线按 journey 步骤完整走一遍，每条不超过 3 分钟。走得顺再开 v2。

## 评审检查清单

1. **优先级**：v1 的 25 项里，有没有应该挪到 v2 的？v2 有没有应该提到 v1 的？
2. **重复**：P107 与 P103 是同一页面带状态，还是两个独立页面？
3. **跨终端复用**：P205、P211、P213、P214 列出"PC + APP"，确认要不要在 W2 骨架阶段就抽公共组件？
4. **节奏**：W3 主线 1 + W4 主线 3 + W5 主线 4 同步推进，会不会人手紧张？是否串行做更稳？
5. **首页**：P000 的 4 大主线卡片设计，需要在 W2 同步给设计师还是 Claude 直接出？

## 使用方式

- W2 开始：把整张表的 v1 行同步成 `src/router/index.ts` 路由占位（不需要写组件，先用 `<router-view />`）
- 每完成一项：更新本表的"状态"列，并把 mock 数据补到 `src/mock/` 同名文件
- 每周 review：拿这张表 + journey 文档逐条检查覆盖情况，超进度的标 `✓`，落后的标 `△`
