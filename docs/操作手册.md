# 圣蛇蛇伤原型 · 操作手册（v1）

> 面向：团队内部对齐 / 设计师评审。
> 目标：5 分钟把环境跑起来，按 4 条主线各 3 分钟走查一遍。
> 当前范围：v1（4 条主线骨架可演示）。v2/v3 页面尚未做，点到会显示「待实现」占位。

---

## 一、快速启动

前置：Node 18+（Vite 5 要求）。

```bash
npm install      # 首次运行；依赖已在 package.json
npm run dev      # 启动开发服务器
```

打开终端输出的地址，默认 `http://localhost:5173`（被占用会自动顺延为 5174 等，**以终端输出为准**）。

其它命令：

```bash
npm run build    # 生产构建（含 vue-tsc 类型检查）
npm run preview  # 预览构建产物
```

## 二、界面总览

- **左侧菜单**按「终端」分组（不是按业务模块），右侧是内容区。
- **患者端 / 医生端 APP** 的页面在右侧用 **375px 手机壳**模拟；**医生端 PC / 内网端 / 系统能力**铺满。
- 顶部：当前角色选择、演示模式开关、推送计数、面包屑（主线 + 页面号）。
- 菜单 5 个分组：

| 分组 | 终端 | 主要页面 |
|---|---|---|
| 患者端（小程序） | 手机壳 | 登录/首页、应急求救、我的就诊、健康陪护 |
| 医生端 PC | 铺满 | 救助工作台、多中心分诊（转诊/MDT/共享） |
| 医生端 APP | 手机壳 | 收件箱、移动就诊、移动分诊 |
| 内网端（专病库） | 铺满 | 数据接入监控（冷热双通道） |
| 系统能力 | 铺满 | 角色与权限、医院与资质 |

### ⚠️ 菜单是「页面索引」，主线流程才是「完整故事」

带 **`:id` 的详情页**（就诊进度、患者实时视图、转诊详情、MDT 会诊室、就诊二维码…）从左菜单**直接点**时，会用占位 id `demo` **自动回退到一条预置数据**，让你能直接预览页面长什么样（不会出现空态）。

但要看**真实的业务联动**（你刚发起的那条 SOS / 转诊所对应的详情），请：
- **按主线流程走**（从 SOS / 列表 / 收件箱点进去，会带真实业务 id），或
- **跨终端回看时用浏览器「后退」**——SPA 内状态常驻，后退能保留真实 id，刷新则重置为预置数据。

## 三、四条主线走查脚本

> 每条 ≤ 3 分钟。括号内是页面号，方便对照 `docs/page-inventory.md`。

### 主线 1 · 蛇伤急救（患者端 ↔ 医生端 PC，跨终端联动）

1. 患者端 → 应急求救 → **求救首页**（P101）。点中间红色「一键 SOS」→ 模拟定位 → 自动跳到就近医院列表，顶部提示「已发起求救」。
2. **就近医院列表**（P102）：有蛇伤资质的医院排在前（无资质的「不可选」）。选「县人民医院」点「选择并前往」→ 跳到就诊进度页（真实事件 id），状态轴显示「已选定医院」。
3. （可选）点「上报现场信息」（P104）填症状/照片/语音 → 返回，状态推进到「已上报现场」。
4. 切左菜单到 医生端 PC → 救助 → **救助工作台**（P201）：刚才那条求救（患者 **张建国**）出现在事件列表，顶部「待处理事件」计数 +1（连同预置的 李德海、赵秀兰 两条）。
5. 点该行「查看」→ **患者实时视图**（P202）：看到现场上报、**蛇种图像识别算法占位**（黄色块）、患者档案（专病库 D1）、患者上传媒体（对象存储 D2）。点底部「**接诊此患者**」→ 提示「已接诊」。
6. （可选）点「推送自救指引」（P203）选模板推送 → 提示「已推送到患者端」；点「填写就诊记录」（P205）填蛇种/血清/处置保存 → 状态进入「治疗中」。
7. **看跨终端联动**：浏览器**后退**回到患者就诊进度页 → 出现绿色卡片「**王医生 已接诊，正在远程查看你的情况**」，并能看到医生推送的自救指引。

> 这一步是这套原型最核心的卖点：患者端和医生端共享同一份状态，一端操作另一端实时可见。

### 主线 3 · 多中心协作（医生端 PC 发起 → 医生端 APP 接收）

1. 医生端 PC → 多中心分诊 → **转诊申请**（P206）：选接收医院（已排除本院）、填原因、选紧急度 → 提交 → 跳到转诊跟踪页（真实 id），状态「待接收方确认」。
2. 医生端 APP → 通讯 → **收件箱**（P221）：三个分区都有内容——转诊（预置 **周国强·危急** + 你刚发的那条）、MDT 邀请（**李德海**）、共享给我的（**赵秀兰**）。
3. 点转诊项 → **转诊申请详情**（P207）→ 接受 / 拒绝。
4. **MDT**：PC「MDT 邀请」（P209）选专家 + 时间提交 → APP 收件箱点开 MDT（P210）→ 接受（全部受邀人接受后状态变「已确认」）。
5. **共享**：PC「共享患者」（P212）选对象 + 有效期提交 → APP「共享给我的患者」（P213）查看。

> 说明：演示里 PC 当前医生固定为 **王建华**（发起方），APP 收件箱为**接收方视角**。身份为演示便利混用，目的是让每个分区都有数据可看。

### 主线 4 · 健康陪护（患者端，单终端 + 状态机演示）

1. 患者端 → 健康陪护 → **我的随访计划**（P108）：出院后自动生成的时间轴（第 3/7/30/90/180/365 天）。
2. **用药打卡**（P110）：点「已服 / 漏服」→ 圆环依从率实时变化；漏服会提示「30 分钟后再次提醒」（呼应频次控制）。
3. **陪护对话**（P111）：发消息或点快捷回复 → AI 机器人按脚本回复；**回复几轮后对话自动结束**，演示「状态机不回环、防死锁」（呼应 journey-4 系统约束）。顶部黄色条 = NLP 算法接入点。
4. **复查详情**（P109）。

### 主线 2 · 数据底座 + 系统能力

1. 内网端 → 数据接入 → **数据接入监控**（P301）：热通道 / 冷通道两张卡 + 「网络边界」告警 + 冷热 Tab 切换的源表格（7 个源）。对应 `docs/data-flow.md` 的冷热双通道设计。
2. 系统能力 → **角色与权限**（P402）、**医院与资质**（P403）。
