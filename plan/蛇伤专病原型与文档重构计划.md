# 蛇伤专病原型与文档重构计划

## Summary

- 新建 `docs/蛇伤专病平台产品总纲.md` 作为唯一 source of truth，后续只维护这一份。
- V1 主演示闭环改为：患者小程序求救 → 医生 PC 接诊救助 → 手填/补录医疗信息 → 就诊记录 → 患者查看就诊信息。
- V2 扩展协作与互动：转诊、MDT、患者 360、医生 APP、医患消息、基础随访。
- V3 扩展数据治理与智能化：专病库治理、CRF、大屏、科研分析、AI 辅助能力。
- 原型页面按“业务主线”重新收敛，隐藏偏技术的“数据接入监控”，去掉冷热双通道表达。

## Key Changes

### 文档重构

- 新建总纲文档，包含：业务目标、角色终端、业务流程、数据流转、模块清单、版本规划、待客户确认事项。
- 将 `docs/data-flow.md`、`docs/information-architecture.md`、`docs/page-inventory.md`、`docs/journeys/*` 的有效内容合并进总纲。
- 旧文档不再并行维护，统一移动到“历史参考/归档说明”语义下，避免多处内容漂移。
- `人民蛇伤模块.md` 不再作为主规划文档，只作为早期模块脑图来源引用。

### 数据流转口径

- 删除“冷热双通道”设定，改为单一接口/同步通道。
- 明确系统拆成两个应用：内网应用 + 内网数据库；外网应用 + 外网数据库。
- 外网患者/医生应用与内网应用通过接口交互，具体接口方案标为待技术确认。
- 医院 HIS/LIS/PACS/120 数据由内网应用对接；外网缺失的医疗数据允许医生手填。
- 脱敏口径调整为：前端展示脱敏，后端保留复核能力；不在原型阶段展开复杂隐私边界。

### 原型页面调整

- 首页与演示导览从“四条并列主线”改成“三层故事”：V1 急救接诊闭环、V2 协作随访、V3 数据治理科研。
- 左侧菜单隐藏“数据接入监控”，保留路由可选但不作为业务演示入口。
- 医生端 V1 只保留 PC 作为主演示终端；医生 APP 页面移动到 V2。
- 转诊、MDT、共享患者从 V1 移到 V2，并在页面上标注“V2 协作能力”。
- 患者 360 保留为医生端外网能力：有数据就展示，无医疗数据时提供手填/补录入口。
- 质控命名暂不改，但在总纲中解释为“医生与患者信息交互相关页面”；真正的数据质量控制归入 V3 专病库治理。
- 内网质量控制页面增加“查阅原文/复核依据”的规划说明，作为 V3 数据治理能力展示点。

### 版本规划

- V1：最小急救与接诊闭环，包括患者求救、医院推荐、现场上报、医生 PC 救助、就诊记录、患者就诊历史。
- V2：多中心协同与持续服务，包括转诊、MDT、医生 APP、患者 360、医患消息、基础随访、培训。
- V3：数据资产与智能化，包括数据治理、查询统计、CRF、科研分析、大屏、AI 辅助诊疗、知识库/特征库。
- 所有页面与模块必须在 UI 上显示版本标签，并标注依赖关系，例如“AI 建议依赖 V3 数据治理/知识库”。

## Test Plan

- 检查左侧菜单：V1 演示中不出现“数据接入监控”、医生 APP、MDT、转诊等 V2/V3 入口。
- 检查首页和版本规划页：V1/V2/V3 定义与总纲完全一致。
- 按 V1 主线完整走查：患者小程序求救 → 医生 PC 接诊 → 手填医疗信息 → 保存就诊记录 → 患者查看记录。
- 检查 V2/V3 页面：未实现或依赖未满足的能力均有清晰版本标签和占位说明。
- 检查文档：除新总纲外，其它 docs 文档明确标记为历史参考或从总纲派生，不再作为规划依据。

## Assumptions

- 实际目录是 `docs`，不是 `doc`；后续 source of truth 放在 `docs` 下。
- V1 医生端采用医生 PC，不同时维护医生 APP。
- “质控模块”名称暂时保留，但文档中明确它不是内网数据质量控制。
- 原型阶段优先讲清业务闭环，不展开接口安全、权限模型、隐私边界和算法实现细节。
