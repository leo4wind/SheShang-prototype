# 蛇伤专病 PRD 1.1 指导文档（合一稿）

## Context（为什么做这件事）

针对当前《人民蛇伤模块.md》+ `docs/` 一堆规划文档 + Vue 原型，做了三轮 AI 评审（deepseek/gpt/gemini）和会议讨论（见 `discuss/`），暴露出三类断层：

1. **版本切分混乱**：`v1/v2/v3` 只是页面优先级标签，不等于能力成熟度，出现「页面 v1 但依赖 v2/v3 底座」的倒挂（如 v1 随访打卡却没有 v2 医生后台、v2 AI 判定却没有 v3 数据治理）。
2. **架构过度设计**：冷热双通道、复杂隔离/脱敏/权限边界，超出原型演示需要。
3. **文档分散漂移**：`人民蛇伤模块.md`（功能清单）与 `docs/journeys/*`、`data-flow.md`、`page-inventory.md`、`information-architecture.md` 多处口径不一致，难以维护。

**目标产出**：一份 **PRD 1.1**（`docs/蛇伤专病PRD-v1.1.md`），作为**唯一 source of truth**，内含流程图 / 数据流 / 模块清单 / 版本说明 / 用户故事，并附「原型改造清单」指导下一步出新原型图与客户对齐。旧文档归档、不再并行维护。

> 本次产出 = 这一份 PRD 文档（含改造指导）。**原型代码改造是下一步**（客户对齐后执行），PRD 内以「原型改造清单」形式列出，本阶段不改代码。

## PRD 1.1 文档结构（要写成的内容）

### 1. 文档说明
版本 1.1、定位为唯一 source of truth、取代文档清单、修订记录。

### 2. 业务目标与范围
一句话产品定位（蛇伤专病：急救闭环 + 多中心协同 + 数据资产）；原型阶段目标 = 跑通业务闭环并与客户对齐，不展开接口/权限/算法实现。

### 3. 角色与终端
沿用 `roles.md`：7 类角色 × 4 终端（患者小程序 / 医生 PC / 医生 APP / 内网 PC）。标注 V1 仅启用 患者小程序 + 医生 PC + 内网 PC（最小导入）。

### 4. 业务流程图（Mermaid）
- **主干流程**（V1 急救接诊闭环）：患者 SOS → 就近医院推荐 → 现场上报 → 医生 PC 救助工作台 → 患者实时视图 → 自救指引推送 → 到院二维码 → 蛇伤判定(规则表单) → 手填就诊记录 → 患者查看就诊历史。
- **求救事件状态机**：V1 画 happy path + **关键终态**（患者取消 / 非蛇伤关闭 / 弱网转电话短信兜底 / 已到院→治疗中→已出院）；**完整终态**（失联关闭 / 危重升级 ICU / 120 接管 / 24h 重复求救合并）标 V2/V3。
- **V2/V3 扩展流程**：多中心协同（转诊/MDT/共享）、随访闭环（出院→随访计划→打卡问卷→异常触发医生→回流专病库）、数据治理流水线（导入→落库→脱敏→清洗→映射→质控→锁定）各一张，明确版本归属。

### 5. 数据流转
- 单通道总图（Mermaid）：源（HIS/LIS/PACS/120/旧专病库/医生录入 在内网；患者小程序在外网）→ 内网应用统一接入 → 专病库 → 消费侧（接诊/协同/随访/科研）。
- 两应用边界：外网应用 ↔ 内网应用走接口（**方案待技术确认**），C 端不直连内网。
- 脱敏口径：前端展示脱敏 / 后端留复核。删除冷热双通道与 Lambda/Kappa 表述。

### 6. 模块清单（按终端 × 模块，带版本 + 依赖）
一张总表，列：模块 / 页面 / 终端 / 版本 / 依赖 / 状态。版本切分（模块粒度，页面级明细在表内）：

- **V1 最小急救接诊闭环**：患者端应急求救（SOS/医院列表/上报/等待页/二维码/弱网兜底）+ 就诊历史；医生 PC（救助工作台/患者实时视图/自救指引/蛇伤判定-规则表单/就诊记录）；内网最小导入（旧专病库导入+字段映射+去重+错误提示）；系统（医院与资质、基础角色）。
- **V2 多中心协同 + 持续服务**：医生 APP 整体；转诊/MDT/共享患者；患者 360（医生端+内网端）；我的患者群组；蛇伤判定 AI 占位；医患消息/消息任务中心雏形；基础随访（随访计划管理/用药打卡/复查/陪护对话/用药情况/患者消息）；防轰炸频控配置；培训中心/管理；HIS/LIS/PACS/120 接入；落库总览/同步异常/多维查询/统计分析；患者身份绑定（到院匹配 MPI）。
- **V3 数据治理 + 科研 + 智能化**：完整治理（脱敏规则/清洗/映射工作台）；质量控制（质控工作台/质疑工单+查阅原文/数据答疑）；科研 CRF/数据流转大屏；历史判定复盘；AI（图像识别/Agent 初诊/治疗路径）；陪护增强（随访问卷/知识中心/打卡日历/我的健康）+ 随访统计端。

### 7. 版本说明
- V1/V2/V3 目标定义（一句话各自解决什么）。
- **能力矩阵**：数据底座 / 急救 / 接诊 / 协同 / 随访 / 科研 / AI 各自在哪个版本成熟。
- **依赖链**：标出前置 vs 增强（如随访闭环依赖医生后台、AI 依赖数据治理）。

### 8. 用户故事
按 **角色 × 主线** 组织，每条格式：`作为<角色>，我想<动作>，以便<价值>` + 版本标签 + 验收要点。V1 聚焦急救闭环 7 步主线；V2/V3 列关键故事不求全。

### 9. 原型改造清单（指导下一步出图/改代码）
逐条可执行项，供客户对齐后落地：
- 左菜单隐藏「数据接入监控」；医生 APP 节点整体标 V2 并从 V1 演示路径移出。
- 转诊/MDT/共享、患者 360、随访打卡等改标 V2；蛇伤判定 V1 去掉 AI、保留规则表单，AI 占位标 V2。
- 首页/版本规划页：四条并列主线 → 三层故事（V1 急救闭环 / V2 协同随访 / V3 治理科研）。
- 数据流大屏：去掉冷热双通道切换，改单通道 + 内外网边界水印。
- 质控工单（V3）：增加「查阅原文/复核依据」占位入口。
- 全局：每页加版本标签 + 依赖提示组件；缺医疗数据处提供「手填补录」入口。

### 10. 待客户确认事项（PRD 显式列出，原型打标）
- 内外网两应用的接口/同步/隔离方案。
- 共享患者权限模型（按患者/病例/时间/字段/机构授权）。
- 医生端 V1 终端最终取舍（暂定 PC，客户可改 APP）。
- 检验/影像数据待 V2 HIS 接入解锁（原型打 `[V2 接入后解锁]` 占位）。
- 血清库存（赛伦生物）、地图 SDK 接入点。
